# antislop audit 001 (2026-11-15)

Mode: audit of the existing UI. Method: a pattern search over `src/` and `App.tsx`, plus the screens and
components read during the security review. The app was not rendered, so everything about contrast, focus and
layout on a real screen is marked unverified. Priority follows the rule tier: Hard Gate is HIGH, Purpose-Gate is
MEDIUM, Quality Locks are LOW.

Reply with the numbers you want fixed. Numbers not named are not touched.

## Findings

| # | Priority | Rule | Finding |
|---|---|---|---|
| 1 | HIGH | R-37 | There is no `DESIGN.md` or other written direction. A redesign without it can only remove slop; it cannot add identity, and the result would be a sterile default. |
| 2 | HIGH | R-25 | Contrast is verified for only four pairings (the add-server warning box and scheme chips). Unmeasured: `text-muted-foreground` on translucent cards over artwork, and `text-white/75` on the 60%-opacity gradient header in `HostCard`. |
| 3 | HIGH | R-32 | Keyboard operation and a visible focus indicator are not verified for the custom `View` buttons, switches and chips (no focus styles were found in the code). |
| 4 | MEDIUM | R-04 | Emoji and symbol glyphs are the icon language: 93 uses in 25 files (`FilesScreen` 16, `SnapshotsScreen` 9, `ShardsScreen` 8, `SchedulesScreen` 6, `ShardScreen` 6). Nine SVG menu icons exist in `assets/menu/` but are used only in the main menu, so the icon language is mixed. |
| 5 | MEDIUM | R-01, R-29 | Server cards take one of six rainbow gradients by index (`SERVER_COLORS` in `servers.ts`: violet-fuchsia, sky-indigo, emerald-teal, amber-orange, rose-pink, cyan-blue). That is far more than 2-3 core colours plus one accent, and the colour marks nothing about the server. |
| 6 | MEDIUM | R-01 | The violet-to-blue gradient is the default fill for primary buttons, the PIN pad OK button, the console Send button and the `HostCard` header. |
| 7 | MEDIUM | R-12 | `shadow-lg` sits on almost every card (52 uses in 25 files), so every surface floats and elevation says nothing. |
| 8 | MEDIUM | R-10, R-13 | Glass treatment is the default surface: translucent `bg-card/85` cards with a white hairline border, plus a decorative backdrop on 13 screens (76 uses in 28 files). |
| 9 | MEDIUM | R-14, R-05 | Screens are stacks of identical bordered cards with the same classes, whatever the content. There is no hierarchy between the thing the user came to do and the rest. |
| 10 | LOW | R-11 | 53 `rounded-full` uses (chips, pills, switches) beside `--radius` cards. Check that pills are used for state and not as the default shape. |
| 11 | LOW | R-09 | Status badges use pill shapes with a dot (`AmpBanner`). Fine where the dot marks a real state (Online, Offline); not checked for every screen. |
| 12 | LOW | R-27 | Empty, loading and error states exist on the screens read, but were not checked on every screen. |
| 13 | LOW | R-06 | Typography was not audited. |

## Passed

- R-15, R-16: no generic CTAs and no marketing buzzwords in the UI text.
- R-17, R-18, R-36, R-38: no invented statistics, testimonials or claims. The home screen says the app is unofficial.
- R-21: dark only, with the reason written down (the artwork). R-30: it does not copy another product.
